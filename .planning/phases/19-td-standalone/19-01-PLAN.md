### 4. Add a useEffect that launches the scene when entering standalone TD mode

```ts
useEffect(() => {
  if (pageMode !== 'tower-defense-standalone') return;
  // Reset the started-scene flag — Boot may have already started Exploration on the
  // initial cold-boot page, but for TD-standalone we want a fresh BreachDefense.
  let cancelled = false;
  const launch = () => {
    if (cancelled || !gameRef.current) return;
    const game = gameRef.current;
    // Stop any other scenes that may be running. ExplorationScene is the realistic
    // suspect (full-game / demo path). BreachDefense itself shouldn't be active.
    if (game.scene.isActive('Exploration')) game.scene.stop('Exploration');
    if (game.scene.isActive('BreachDefense')) game.scene.stop('BreachDefense');
    // Start BreachDefense in standalone mode (init data omitted = encounterId undefined).
    game.scene.start('BreachDefense');
  };
  // gameRef may not be set yet on first render — poll briefly.
  if (gameRef.current) {
    launch();
  } else {
    const poll = setInterval(() => {
      if (gameRef.current) {
        clearInterval(poll);
        launch();
      }
    }, 50);
    setTimeout(() => clearInterval(poll), 5000);
    return () => { cancelled = true; clearInterval(poll); };
  }
  return () => { cancelled = true; };
}, [pageMode]);
```

### 5. Add a useEffect for BREACH_VICTORY / BREACH_GAME_OVER listeners

Active only while in standalone TD mode. Updates result state — no scoring, no save writes, no encounter registry writes.

```ts
useEffect(() => {
  if (pageMode !== 'tower-defense-standalone') return;
  const onVictory = (data: { securityScore: number; wavesCompleted: number; towersPlaced: number }) => {
    setTdStandaloneResult({ outcome: 'victory', ...data });
  };
  const onGameOver = (data: { wavesCompleted: number; towersPlaced: number }) => {
    setTdStandaloneResult({ outcome: 'defeat', ...data });
  };
  eventBridge.on(BRIDGE_EVENTS.BREACH_VICTORY, onVictory);
  eventBridge.on(BRIDGE_EVENTS.BREACH_GAME_OVER, onGameOver);
  return () => {
    eventBridge.off(BRIDGE_EVENTS.BREACH_VICTORY, onVictory);
    eventBridge.off(BRIDGE_EVENTS.BREACH_GAME_OVER, onGameOver);
  };
}, [pageMode]);
```

### 9. Play Again / Back to Menu handlers

```ts
const handleTdPlayAgain = useCallback(() => {
  setTdStandaloneResult(null);
  // BreachDefenseScene exposes onRestart via REACT_RESTART_BREACH. After restart it
  // returns to WAITING; React then needs to emit REACT_START_BREACH to re-arm wave 1.
  eventBridge.emit(BRIDGE_EVENTS.REACT_RESTART_BREACH);
  eventBridge.emit(BRIDGE_EVENTS.REACT_START_BREACH);
}, []);

const handleTdBackToMenu = useCallback(() => {
  // Match the existing demo-Esc clean-reset pattern: full reload returns to the
  // StartMenu cold-boot screen with all in-memory state (Phaser scene, ref flags,
  // tdStandaloneResult) freshly torn down. No save mutation occurred during TD,
  // so reload restores the pre-TD state cleanly.
  window.location.reload();
}, []);
```

## Save-Isolation Audit

The persistence `useEffect` at line ~206 fires on `gameState.state` changes. Standalone TD must NOT mutate `gameState`:
- We do NOT call `gameState.addScore` or `gameState.recordEncounterResult` in this code path.
- We do NOT call `gameState.setCurrentRoom`, `completeRoom`, `completeNPC`, etc.
- Therefore the persistence effect's deps don't change, and `writeSave` is not invoked from a TD round.
- Demo session: we never call `startDemo()` from this path. `isDemoActive()` returns false throughout.

The only side effect TD has on localStorage is the existing `sfx_muted` toggle (read-only during the round; written only if the player toggles mute). That key has been a cross-mode setting since v1 and is not a save-state mutation.

## Implementation Adjustments (vs original Plan)

1. **EncounterGameUI tower list:** Original plan said `availableTowerIds={[]}` would be a "no filter" sentinel; reading the component revealed it actually filters TOWERS by `availableSet.has(id)`, so an empty list shows zero towers. Final wiring passes the explicit list `['MFA', 'PATCH', 'FIREWALL', 'ENCRYPTION', 'TRAINING', 'ACCESS']`.

2. **Mid-game educational pauses:** BreachDefenseScene's standalone branch (`encounterId === null`) PAUSES the wave loop on waves 3, 5, 7, 9 and waits for `REACT_DISMISS_TUTORIAL`. Legacy `BreachDefensePage.tsx` (now dead code) used to surface a TutorialModal. Standalone TD as sponsor-pitch is self-contained, so we added a React-side `BREACH_WAVE_COMPLETE` listener that immediately re-emits `REACT_DISMISS_TUTORIAL`. No scene refactor needed.

3. **`totalWaves` HUD field:** EncounterGameUI's HUD shows `WAVE x/totalWaves`, defaulting to 3. The scene's broadcastState payload didn't carry `totalWaves`, so the HUD would show "1/3" through 10 standalone waves. Added `totalWaves: this.getActiveWaves().length` to broadcastState — additive change, doesn't break encounter mode (still 4 there).

4. **Handler ordering:** Original plan declared the TD handlers near the existing start-menu handlers. TS caught a "used before declaration" error because the standalone-TD-Esc useEffect needed `handleTdBackToMenu` in its deps. Final placement: TD handlers declared above the standalone-TD useEffects, handler-original-location anchor comment retained for grep discoverability.
