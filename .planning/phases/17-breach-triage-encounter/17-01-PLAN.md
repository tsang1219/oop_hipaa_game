**Types (export all):**
```typescript
export type TriageOption = {
  id: string;
  label: string;          // short, punchy — fits a button
  correct: boolean;
  explanation: string;    // shown when this option is picked AND wrong, or as reinforcement — teaches the rule plainly, cites the CFR section at the end e.g. "(45 CFR §164.404)"
};

export type TriageFollowUp = {
  notifyPrompt: string;       // e.g. "Who has to hear about this?"
  notifyOptions: TriageOption[];   // exactly 3, one correct
  timelinePrompt: string;     // e.g. "And by when?"
  timelineOptions: TriageOption[]; // exactly 3, one correct
};

export type TriageIncident = {
  id: string;
  headline: string;       // terse incident-ticket title, e.g. "LAPTOP MISSING — ONCOLOGY"
  detail: string;         // 1-2 sentences, written like a real incident report with personality (Nintendo Test — not a compliance doc)
  reportable: boolean;
  classificationExplanation: string;  // shown on wrong classification — why it is/isn't a breach, ends with CFR cite
  followUp?: TriageFollowUp;          // REQUIRED iff reportable === true
  difficulty: 1 | 2 | 3;              // drives per-incident timer in the overlay (1=14s, 2=12s, 3=10s)
};

export type TriageIncidentSet = {
  id: string;                          // 'breach-triage-set-1'
  npcId: string;                       // 'priya_privacy_officer'
  npcName: string;                     // 'Priya'
  npcRole: string;                     // 'Privacy Officer'
  contextCard: { title: string; body: string };
  incidents: TriageIncident[];
  passingAccuracy: number;             // 0.7
  takeaways: [string, string];
};

export function getTriageIncidentSet(id: string): TriageIncidentSet | undefined
```

**The 9 incidents** (order = spawn order; interleave difficulties so the run ramps up):

1. `misdirected-fax` (d1, REPORTABLE): Discharge summary faxed to Gino's Pizzeria instead of the PCP — Gino called the front desk, confused and concerned. Reportable: impermissible disclosure of unsecured PHI, presumed a breach unless a documented risk assessment shows low probability of compromise (§164.402). Follow-up: notify the patient (correct) / patient + local media (wrong — media is only for 500+ breaches) / nobody, it was an accident (wrong). Timeline: without unreasonable delay, ≤60 days from discovery; logged for the annual OCR report since <500 (correct) / within 72 hours (wrong — that's GDPR, not HIPAA) / only if the patient asks (wrong).
2. `unencrypted-laptop` (d1, REPORTABLE): Unencrypted laptop with 1,200 patient records stolen from a car in the staff lot. Reportable, AND it crosses the 500 threshold. Follow-up: notify = patients + OCR + prominent media outlet serving the state (correct, §164.404/406/408) / patients only (wrong) / OCR only, quietly (wrong). Timeline: all three without unreasonable delay, ≤60 days from discovery — OCR notice is contemporaneous with patient notice for 500+ (correct) / media immediately, patients within 6 months (wrong) / annual log entry is enough (wrong — that's <500 only).
3. `encrypted-laptop` (d2, NOT reportable): Laptop left in a rideshare — full-disk AES-256 encryption, key not compromised, device wiped remotely. Encryption safe harbor: encrypted PHI is not "unsecured PHI," so no breach notification required (§164.402 definition of unsecured PHI). The deliberate trap-pair with #2.
4. `hr-snooping` (d2, REPORTABLE): HR rep opened a coworker's behavioral-health visit notes the week before a promotion decision. No job-related need. Intentional unauthorized access = breach; notify the affected employee-patient; <500 so annual OCR log. The "it stayed in-house" instinct is the trap.
5. `good-faith-glance` (d2, NOT reportable): Float nurse opened the wrong J. Ramirez chart, realized within seconds, closed it, self-reported immediately. Good-faith, unintentional acquisition by a workforce member acting within authority, no further use or disclosure — statutory exception (§164.402(1)(i)).
6. `vendor-breach` (d2, REPORTABLE): Billing vendor (business associate) reports attackers exfiltrated 3,400 patient records — and the vendor sat on it for three weeks. BA must notify the covered entity without unreasonable delay, ≤60 days from discovery (§164.410); CE then owns patient + OCR + media notice (>500). Follow-up timeline options should include the BA angle.
7. `internal-misuse` (d2, REPORTABLE): Registration clerk exported a patient contact list to advertise her side wellness business. Impermissible use for personal gain — breach; affected patients notified; <500 annual log.
8. `deceased-records` (d3, NOT reportable): Historical society requested records of a patient who died in 1962 — released without authorization. PHI protections end 50 years after death (§164.502(f)) — 60+ years deceased means it's no longer PHI, so no breach. The hardest call in the set.
9. `ransomware` (d3, REPORTABLE): Ransomware encrypted the file server holding unsecured PHI; no exfiltration proof either way. Per OCR guidance, ransomware encryption of unsecured PHI is presumed a breach unless a documented risk assessment demonstrates low probability of compromise. >500 affected (e.g., 2,800 records) — full patient + OCR + media follow-up.

**Content rules:**
- HIPAA accuracy is non-negotiable. NOTE: the roadmap's shorthand "immediate media notice for >500 records" is a simplification — the accurate rule (use this) is: media notice for breaches affecting MORE THAN 500 residents of a state/jurisdiction, without unreasonable delay and ≤60 days (§164.406); OCR concurrent for 500+, annual log (within 60 days of calendar year end) for <500 (§164.408). Never write "72 hours" as a correct answer — use it only as the GDPR-trap wrong option.
- Tone: incident-ticket deadpan with personality (the Gino's Pizzeria call, the vendor who "sat on it for three weeks"). Every explanation teaches *why* in plain language and ends with the CFR cite in parentheses. No paragraph longer than 2 sentences (these render under time pressure).
- contextCard + takeaways: Priya the Privacy Officer is triaging the incident queue mid-Act-3 crisis (CLAUDE.md Commandment 4 — she's exhausted, this is her third queue today, she's precise because she has to be). Takeaways: (1) the breach presumption + encryption safe harbor, (2) the 60-day clock + 500-record threshold for media/OCR.
